# Agent instructions

HalfPast Meter is a Home Assistant custom integration (domain `bright_meter`)
that imports UK smart-meter data from Hildebrand's Glowmarkt API as hourly
external statistics. It started from
[existentia/hildebrand-glow-ha](https://github.com/existentia/hildebrand-glow-ha)
v0.1.2 under MIT.

## Build, test, lint

```bash
make venv      # .venv with the pinned Home Assistant and test plugin (needs uv)
make check     # ruff, pytest, then both generators with --check; what CI runs
make hassfest  # Home Assistant's manifest validation (needs Docker)
make diagram   # redraw docs/assets/*.svg and the generated tables
```

Run `make check` before and after a change; anything green stays green.
`requirements_test.txt` pins one Home Assistant release; bump it with the
house's version, never to a beta. CI also runs the suite on the newest release
(`.github/ha-latest/requirements.txt`) and, weekly, every workflow.

## Layout

- `custom_components/bright_meter/`: the integration. `api.py` is the HTTP client
  and knows nothing about Home Assistant; `coordinator.py` polls and imports;
  `statistic_ids.py` assigns and stores statistic ids; `energy_dashboard.py`
  reads and switches the Energy dashboard sources; `config_flow.py`,
  `sensor.py`, `diagnostics.py`; `brand/` holds the icons.
- `tests/`: `const.py` has `FakeGlowmarktClient`, the API including its misbehaviour.
- `tools/`: generators (`gen_diagram.py`, `gen_docs.py`, `gen_social_preview.py`).
- `scripts/`: `install-on-ha.sh` ships the committed component over SSH
  (see `.env.example`); `check-login.py` tests a Glowmarkt login.
- `docs/`: start at `docs/README.md`. Tables with a source of truth are
  generated; never edit them or the SVGs by hand.

## Do not change

- The domain `bright_meter` and the `bright_meter:` statistic ids. Renaming either
  orphans every imported statistic on every install. New ids come only from
  `statistic_ids.py` and are stored, never derived from site names.
- Environment variable names, public URLs, entity ids, `hacs.json` keys.
- Both copyright lines in `LICENSE` and `custom_components/bright_meter/LICENSE`.

## Importer rules (each pinned by a test)

Readings are requested with `nulls=1` and malformed answers raise; nothing at or
after `last-time` is imported; a gap is never a row; hours are de-duplicated and
summed in time order; nothing is written until every read succeeded, then one
batch; a stored row a pass has no reading for is rewritten flat; the anchor
search reaches the deepest history; the last week is re-read every pass; local
days are built from local midnights (23, 24 or 25 hours).

Not verified against a live account (keep the README's list in step): the
catch-up rate limit, which half-hour carries the standing charge in the cost
stream, the tariff payload's real shape, and gas in m3.

## Conventions

- A behaviour change starts with a test that fails without it.
- Conventional commits (`fix:`, `feat:`, `docs:`, `refactor:`, `ci:`, `chore:`)
  authored by the repo owner. No co-author trailers, session ids or
  "generated by" lines in commits, PRs, issues or comments.
- Documentation must be true of the code: no hand-typed counts that can drift.
- Never commit secrets, keys, tokens, IP addresses, private hostnames or
  personal e-mail. The one public contact address is caputodav@gmail.com.
- Never force-push `main`; it is protected (pull requests, required checks).
- The social preview, `docs/assets/social-preview.png` (`make social`), is
  uploaded by hand in the repository settings.
- Releases: roll `[Unreleased]` in `CHANGELOG.md` into a version, bump
  `manifest.json`, tag `vX.Y.Z`, `gh release create`.
